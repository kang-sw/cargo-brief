# LSP grep-based fallback symbol resolution

## Context

**From ticket:** `resolve_symbol()` uses `workspace/symbol` as its sole
resolution strategy. This fails for external dependency types (World, App),
common method names (new, get), and qualified paths (Type::method). The fix
is a fallback that greps workspace source for usage sites, then uses
`textDocument/definition` to resolve the canonical definition position.

**Key decision:** The fallback lives entirely inside the daemon — no protocol
changes, no new DaemonRequest variants. `resolve_symbol()` is called by all
three query handlers (references, call-hierarchy, blast-radius), so all
benefit automatically.

**Key decision:** Grep is the candidate finder; ra's `textDocument/definition`
is the semantic resolver. False positives from grep (comments, strings) are
filtered because definition returns empty for non-semantic positions.

**Key decision:** Qualified name narrowing — for `hecs::World`, grep for the
full qualified string first (`hecs::World`), then fall back to the bare name
(`World`). This improves precision.

**Key decision:** Disambiguation uses the existing `ResolveResult::Ambiguous`
pattern — no new UX.

## Relevant Files

- `src/lsp/query.rs` — **primary change site**. `resolve_symbol()` gets the
  fallback path. New helpers: `grep_workspace_for_symbol()`,
  `resolve_via_definition()`.
- `src/lsp/daemon.rs` — no changes needed. `handle_request()` already passes
  `&mut transport` and `workspace_root` to query handlers.
- `src/lsp/transport.rs` — no changes needed. `send_request_and_wait()` already
  supports any LSP method including `textDocument/definition`.
- `src/lsp/protocol.rs` — no changes needed. No new request/response variants.
- `src/examples.rs` — reference for file-walking pattern (`collect_rs_files_inner`).
  Not imported; pattern reimplemented in query.rs (simpler, workspace-scoped).
- `src/cli.rs` — update help text to remove "workspace-defined only" caveat.

## Conventions (verified from code)

- All query orchestrators follow the pattern:
  `resolve_symbol() → LSP query → format_*()`. Fallback integrates at the
  resolve_symbol level.
- `transport.send_request_and_wait(method, params)` is the universal blocking
  LSP call. Returns `Result<serde_json::Value>`. Works for any method.
- File URIs use `file:///absolute/path` format. `uri_to_relative()` in query.rs
  strips the workspace root prefix.
- Error handling: query handlers return `Result<String>`. Internal errors
  bubble up; the daemon wraps them in `DaemonResponse::Error`.

## Implementation Steps

### Step 1: Add `grep_workspace_for_symbol()` helper

**File:** `src/lsp/query.rs`
**Delegation:** main

Add a function that walks workspace .rs files and finds lines containing the
symbol name with word-boundary-like matching:

```rust
struct GrepHit {
    uri: String,     // file:// URI
    line: u32,       // 0-indexed
    col: u32,        // 0-indexed, start of matched identifier
}

fn grep_workspace_for_symbol(
    workspace_root: &Path,
    query: &str,        // raw user query, e.g. "hecs::World" or "World"
    max_hits: usize,    // cap to avoid scanning everything
) -> Vec<GrepHit>
```

**Algorithm:**
1. Parse query: split on `::` to get segments. The search term for grep is the
   **last segment** (e.g., `World` from `hecs::World`). If qualified, also keep
   the full string for narrowing.
2. Walk workspace .rs files recursively (skip `target/`, hidden dirs).
3. For each file, read content, scan lines for the search term.
   - First pass (if qualified): look for the **full qualified string**
     (e.g., `hecs::World`). This catches `use hecs::World` and
     `hecs::World::new()`.
   - Second pass (if qualified and first pass empty): fall back to bare name.
   - For bare names: just search for the name.
4. For each matching line, find the column of the identifier (the last segment).
   Use `str::find()` — returns byte offset which equals UTF-16 offset for ASCII.
   **Limitation:** if the line has multi-byte UTF-8 before the match, the column
   will be off. This is acceptable — that hit will fail definition and the next
   hit is tried.
5. Prioritize `use` lines (they're more likely to have clean definition targets).
   Sort: `use` imports first, then other occurrences.
6. Return up to `max_hits` results. Once `hits.len() >= max_hits`, return
   immediately (break outer file loop).

**URI construction** from `PathBuf` (follows `daemon.rs::send_initialize()`):
```rust
let path_str = path.to_str().unwrap_or_default();
let uri = if path_str.starts_with('/') {
    format!("file://{path_str}")
} else {
    format!("file:///{path_str}")
};
```

**File walking:** Walk the entire workspace root recursively, skip `target/`
and hidden dirs (names starting with `.`). Inline implementation, not an import.

### Step 2: Add `resolve_via_definition()` helper

**File:** `src/lsp/query.rs`
**Delegation:** main

```rust
fn resolve_via_definition(
    transport: &mut RaTransport,
    workspace_root: &Path,
    hits: &[GrepHit],
) -> Result<ResolveResult>
```

**Algorithm:**
1. For each hit, send `textDocument/definition` at (uri, line, col).
2. Parse response: definition can be a single Location or an array.
   Extract (uri, line, col) of the definition target.
3. Collect unique definitions keyed by `(uri, line)`.
4. For each unique definition, construct a `SymbolMatch`:
   - `name`: reuse the query's last `::` segment (simple, reliable).
   - `kind`: default to `"symbol"` (no LSP method resolves kind from position).
   - `container_name`: extract from definition URI path relative to workspace
     root, or from the grep hit's container context. For external deps, the
     URI path will show as an absolute path in disambiguation — acceptable.
5. Skip definitions that return empty/null (false positive grep hits).
6. If the definition points to a file outside the workspace (external dep),
   that's fine — we just need the position for references/call-hierarchy.
7. Deduplicate and return:
   - 0 → NotFound
   - 1 → Ok
   - N → Ambiguous

**didOpen concern:** ra should know about workspace files from initialization.
For external dep files (e.g., ~/.cargo/registry/...), ra also indexes them as
part of the workspace deps. If definition fails on a file, skip it (non-fatal).

### Step 3: Wire fallback into `resolve_symbol()`

**File:** `src/lsp/query.rs`
**Delegation:** main

Modify `resolve_symbol()` to try the fallback when workspace/symbol returns
no matches:

```rust
pub fn resolve_symbol(
    transport: &mut RaTransport,
    query: &str,
    workspace_root: Option<&Path>,  // NEW parameter
) -> Result<ResolveResult> {
    // ... existing workspace/symbol logic ...

    match matches.len() {
        0 => {
            // Fallback: grep + definition
            if let Some(ws_root) = workspace_root {
                let hits = grep_workspace_for_symbol(ws_root, query, 15);
                if !hits.is_empty() {
                    return resolve_via_definition(transport, ws_root, &hits);
                }
            }
            Ok(ResolveResult::NotFound)
        }
        1 => Ok(ResolveResult::Ok(matches.remove(0))),
        _ => Ok(ResolveResult::Ambiguous(matches)),
    }
}
```

**Signature change:** Adding `workspace_root: Option<&Path>` to `resolve_symbol`.
This is called from three places in query.rs:
- `handle_references()` — already has `workspace_root: &Path`
- `handle_call_hierarchy()` — already has `workspace_root: &Path`
- `handle_blast_radius()` — already has `workspace_root: &Path`

All callers pass `Some(workspace_root)`. The `Option` allows the existing
unit tests (which don't have a real workspace) to pass `None` and get the
old behavior. Alternatively, always pass the path — simpler.

**Decision:** Always require `workspace_root: &Path` (not Option). All real
callers have it. Update the 3 call sites. Tests that test resolve_symbol
directly would need to be adjusted, but there are currently NO unit tests
for resolve_symbol (it requires a live ra instance).
