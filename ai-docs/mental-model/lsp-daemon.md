# LSP Daemon

## Entry Points
- `src/lsp/mod.rs` — `run_lsp_command()`: validates remote mode is off, loads metadata, dispatches touch/stop/status/references/blast-radius/call-hierarchy.
- `src/lsp/daemon.rs` — `run_daemon_from_args()`: called from `main.rs` early-exit path before clap parsing; `run_daemon()` is the main daemon loop.
- `src/lsp/client.rs` — `ensure_daemon()`, `daemon_dir()`, `cleanup_daemon_files()`: client-side entry points for spawning and locating daemons. Does NOT contain `send_command`.
- `src/lsp/ipc/mod.rs` — platform-gated re-exports of `DaemonIpc`, `send_command`, `cleanup_ipc_files`, `ready_indicator`; Unix uses FIFO+flock, Windows uses atomic-rename files.
- `src/lsp/watcher.rs` — `start_watcher()`: sets up notify-based FS watcher; `DebounceBuffer`: 300ms batching; `build_did_change_notification()`: LSP params construction.
- `src/lsp/query.rs` — `handle_references()`, `handle_call_hierarchy()`, `handle_blast_radius()`: orchestrators for symbol resolve → LSP query → format. `resolve_symbol()`, `prepare_call_hierarchy()`, `incoming_calls()`, `outgoing_calls()` are shared building blocks used by all three handlers.

## Module Contracts
- `run_lsp_command()` guarantees: calls `resolve::load_cargo_metadata()` directly — does NOT build a `PipelineContext`. Returns `Result<()>`, not `Result<String>` — it prints directly to stderr/stdout.
- `daemon_dir(target_dir, workspace_root)` guarantees: canonicalizes the workspace root before hashing. Two clients with symlinked paths pointing to the same directory will share the same daemon. The hash is FNV-1a 64-bit, hex-encoded to 16 chars. Directory is `<target_dir>/cargo-brief-lsp/<hash>` — lives inside the project's `target/` directory for macOS sandbox compatibility (not in `$TMPDIR` or `$XDG_RUNTIME_DIR`).
- `ensure_daemon()` guarantees: liveness check is PID-file alive AND `ipc::ready_indicator(&dir)` exists (the readiness signal — it only appears after `DaemonIpc::setup()` completes, which is called after ra initialization). On stale PID (process dead), calls `cleanup_daemon_files()` then re-spawns. Polls the readiness indicator up to 120 seconds with exponential backoff (50ms → 500ms); on early daemon death, bails immediately with the last 20 lines of `lsp.log`. Returns `Result<PathBuf>` (daemon dir path) — callers pass this to `ipc::send_command()`.
- `ipc::send_command(daemon_dir, request, timeout)` guarantees (Unix): (1) acquires exclusive `flock` on `lsp.lock` — only one client communicates with the daemon at a time; (2) opens `lsp.req` FIFO for writing, sends request, closes write-end; (3) opens `lsp.resp` FIFO O_NONBLOCK, drains stale data, calls `poll()` with caller-supplied timeout, then switches to blocking to read the response; (4) flock is released on return. A timeout surfaces as `anyhow::Error`, not a `DaemonResponse::Error`. This function lives in `src/lsp/ipc/unix.rs`, not `client.rs`.
- `run_daemon()` guarantees: (1) writes PID file before anything else (double-spawn guard); (2) LSP initialize completes before `DaemonIpc::setup()` is called — `setup()` IS the readiness signal; clients that see `ipc::ready_indicator()` will always find an initialized (or failed) ra instance; (3) FIFOs (Unix) are opened with `O_RDWR` for the daemon's lifetime, which prevents `open()` from blocking and eliminates `POLLHUP` on the read end when no client has the write end open; (4) file watcher is started after LSP initialize and before `DaemonIpc::setup()` — watcher failure is non-fatal; (5) idle timeout defaults to 600s, overridable via `CARGO_BRIEF_LSP_TIMEOUT`; (6) on exit calls `ipc::cleanup_ipc_files()` (req/resp/lock) then separately removes `lsp.pid` and `lsp.log`, and attempts `rmdir` (normal, idle timeout, or Stop command — NOT panic or SIGKILL).
- Cleanup split: `ipc::cleanup_ipc_files(dir)` removes IPC-specific files only (`lsp.req`, `lsp.resp`, `lsp.lock` on Unix; plus `lsp.req.tmp`, `lsp.resp.tmp`, `lsp.ready` on Windows). `client::cleanup_daemon_files(dir)` delegates to `cleanup_ipc_files` then removes `lsp.pid` and `lsp.log`. The daemon calls `cleanup_ipc_files` + pid/log removal on exit; the client calls `cleanup_daemon_files` when re-spawning over a stale daemon.
- `handle_request()` guarantees: pure function — takes `&DaemonRequest`, returns `DaemonResponse`, no IO. The main loop handles all FIFO reads/writes around it. Query errors are returned as `DaemonResponse::Error`, not propagated as `Err`.
- `query::handle_references()` guarantees: all output formatting (including source-line reads) happens inside the daemon — the client receives a pre-formatted string via `DaemonResponse::QueryResult { output }`. Source lines are read from disk by the daemon at response time; if a file is unreadable, individual lines are replaced with `<source unavailable>` (non-fatal). Symbol resolution uses a two-stage strategy via `resolve_symbol(transport, query, workspace_root)`: (1) `workspace/symbol` with exact match on the last `::` segment, container name matched as substring — finds workspace-defined items fast; (2) if stage 1 returns 0 matches, greps workspace `.rs` files (skipping `target/` and hidden dirs) for usage sites, then calls `textDocument/definition` on each hit — finds external dep symbols but is significantly slower. `use` lines are sorted first in grep results; up to 15 hits are forwarded to definition lookup. The `workspace_root` parameter must be the canonical workspace root — it is both the grep walk root and the base for `uri_to_relative()` formatting in stage 2 results.
- `query::handle_call_hierarchy()` guarantees: uses `textDocument/prepareCallHierarchy` then `callHierarchy/incomingCalls` or `callHierarchy/outgoingCalls` depending on the `outgoing` flag. `CallHierarchyItem` values are passed through as `serde_json::Value` to preserve the opaque `data` field that ra requires for subsequent calls — do not deserialize into a typed struct. If `prepareCallHierarchy` returns an empty array, the handler returns a "No call hierarchy found" message without an error.
- `query::handle_blast_radius()` guarantees: clamps depth to `[1, 10]` regardless of what the client requests. Performs BFS of incoming callers using `incoming_calls()` at each level. Dedup is keyed on `(uri, selectionRange.start.line)` — two functions at the same line but in different crates would be incorrectly merged (unlikely but possible with re-exports). Output is grouped by depth level.
- `cmd_query()` pattern: calls `ensure_daemon()` to get the daemon dir, then `send_command()` with a 120s timeout (`QUERY_TIMEOUT` constant in `mod.rs`). The 120s budget covers up to 60s daemon-side indexing wait plus query execution time. Output goes to stdout (not stderr) — consistent across all three query commands. `cmd_touch`/`cmd_stop`/`cmd_status` use 5s timeouts.
- `RaStatus` lifecycle: `Initializing` → `Indexing` (first `$/progress` begin seen) → `Ready` (all progress tokens cleared). Fallback: if no `$/progress` ever arrives and uptime exceeds `NO_PROGRESS_FALLBACK_SECS` (10s), status advances to `Ready` automatically. Transitions are logged to stderr.
- `run_daemon()` guarantees: (7) after LSP initialize, `DaemonIpc::setup()` is called while status is still `Initializing` or `Indexing`; query commands (References, BlastRadius, CallHierarchy) block inside `wait_for_ready()` before dispatch — non-query commands (touch, stop, status) are served immediately. `wait_for_ready()` timeout defaults to 60s, overridable via `CARGO_BRIEF_LSP_READY_TIMEOUT`; on timeout, a `DaemonResponse::Error` is sent to the client and the main loop continues.
- `RaTransport` guarantees: `send_request_and_wait()` skips notifications (messages with no `"id"` field), replies to server-initiated requests (messages with both `"id"` and `"method"`, e.g. `window/workDoneProgress/create`) with a null result, and reads up to 10,000 messages before giving up.
- `RaTransport` lifecycle: constructed with direct `BufReader` access to ra stdout. After `spawn_reader_thread()` is called, ownership of the `BufReader` moves to a background thread; `read_message()` switches to channel-based blocking reads, and `try_read_message()` / `read_message_timeout()` become available. Calling `try_read_message()` or `read_message_timeout()` before `spawn_reader_thread()` **panics**, not errors. `spawn_reader_thread()` must be called exactly once — calling it twice panics. In `run_daemon()`, the thread is spawned immediately after `send_initialize()` returns.
- The `lsp` module is cross-platform. `libc` (Unix-only) is used only for FIFO/flock in `ipc/unix.rs`. The `notify` file-watcher dependency is unconditional.

## Coupling
- `main.rs` early-exit: `args[1] == "__lsp-daemon"` is checked BEFORE clap parsing. The `__lsp-daemon` sentinel must always be in position 1. `spawn_daemon()` passes it as the first argument after the binary name and follows with `--workspace-root <path> --daemon-dir <path>`. This positional contract must not be broken.
- `resolve::CargoMetadataInfo.workspace_root` and `.target_dir` are both consumed by this module. All callers of `load_cargo_metadata()` receive these fields; test helpers in `resolve.rs` initialize them to dummy paths.
- `daemon_dir()` uses the CANONICAL workspace root as hash input. If `canonicalize()` fails, the raw path is used as fallback — two clients may hash to different dirs if one succeeds at canonicalization and the other does not.
- PID file is written before `DaemonIpc::setup()` is called. A crash after PID write but before the readiness indicator appears leaves a stale PID pointing to a dead process. `ensure_daemon()` detects this via `process_alive()` and calls `cleanup_daemon_files()` — but only if the PID is a valid u32 and the file is readable. A corrupted PID file blocks daemon restart until manually removed.
- `start_watcher()` spawns an OS-level thread internally. The `RecommendedWatcher` handle is stored as `_watcher: Option<RecommendedWatcher>` in `run_daemon()` stack frame — dropping it on daemon exit stops the OS thread. `fs_rx: Option<Receiver<FileEvent>>` is drained via `try_recv()` on each main-loop iteration.
- The main loop poll interval is 100ms. This is the latency floor for FS-event processing — debounce is an additional 300ms on top.

## Extension Points & Change Recipes
- **Add a new daemon query command**: Add variant to `DaemonRequest` in `protocol.rs` (all query results use `DaemonResponse::QueryResult { output }` — no new response variant needed). Add match arm in `daemon.rs::handle_request()`. Add `handle_*()` orchestrator in `query.rs`. Add `cmd_query()` call in `mod.rs`. Add `LspCommand::*` variant in `cli.rs` and dispatch arm in `mod.rs::run_lsp_command()`. The protocol is JSON-serialized — adding a new enum variant is backward-compatible only if the daemon and client versions match (no versioning mechanism exists).
- **Add a new `LspCommand` subcommand** that does not need a new daemon request: Add variant to `cli::LspCommand`, add match arm in `lsp::mod::run_lsp_command()`. Touch `cli.rs`, `lsp/mod.rs` only.
- **Change idle timeout default**: Change `IDLE_TIMEOUT_SECS` in `daemon.rs`. The env var `CARGO_BRIEF_LSP_TIMEOUT` already overrides it at runtime.
- **Change indexing-wait timeout default**: Change `READY_TIMEOUT_SECS` in `daemon.rs` (default 60s). The env var `CARGO_BRIEF_LSP_READY_TIMEOUT` overrides it at runtime. The client-side `QUERY_TIMEOUT` in `mod.rs` (120s) must remain larger than this value or the client will time out before the daemon returns an error.
- **Change debounce window**: Change `DEBOUNCE_MS` in `watcher.rs`. The value is a `u128` compared against `elapsed().as_millis()` — the window is measured from the first event in a batch, not from the most recent event.

## Common Mistakes
- Adding a new `DaemonRequest` variant without a matching arm in `daemon.rs::handle_request()` — the match is exhaustive so this is a compile error. But sending a new request to an OLD daemon silently fails with a JSON deserialization error on the daemon side (daemon reads malformed message, logs error, continues).
- The `lsp` module output goes to stderr (via `eprintln!`), NOT stdout — except the three query commands which print formatted output to stdout. Asserting on stdout in tests for `touch`/`stop`/`status` will always get empty output.
- `cmd_stop` does NOT call `ensure_daemon()` — it uses `daemon_dir()` directly and checks `ipc::ready_indicator(&dir).exists()`. If the daemon is not running, it silently exits (no error). This is by design but differs from the other commands. Do not hard-code `lsp.req` in this check; the indicator path is platform-specific via `ipc::ready_indicator()`.
- `handle_blast_radius()` depth is silently clamped to 10. A caller passing `depth=0` gets `depth=1` (minimum), not zero results. Not surfaced to the user in the output header.
- The `lsp.req` FIFO open in `ipc::send_command()` (Unix) blocks until the daemon has the read-end open. If the daemon is killed between `ensure_daemon()` returning and `ipc::send_command()` opening the FIFO, the client will block indefinitely on `OpenOptions::new().write(true).open(&req_path)` — there is no timeout on the FIFO open itself.
- `handle_blast_radius()` uses `serde_json::Value` for `CallHierarchyItem` to preserve ra's opaque `data` field. Replacing this with a typed struct will cause subsequent `callHierarchy/incomingCalls` calls to silently return empty results because ra requires the original `data` value round-tripped verbatim.
- `resolve_symbol()` stage 1 (workspace/symbol) filters by container name as a substring (`container.contains(cf)`). A query like `foo::Bar` will match any symbol named `Bar` whose `containerName` contains `foo` — including `my_foo::Bar`. If the workspace has multiple crates with similar module paths, some matches may be silently pre-filtered before the "Ambiguous" branch. This container-substring filter applies only to stage 1; the grep+definition fallback (stage 2) bypasses container filtering entirely.
- The grep fallback in `resolve_symbol()` computes column via `line.find(ident_name)` (first occurrence on the line). If the bare name appears more than once on a line (e.g., `let World: World = todo!()`) `textDocument/definition` resolves the first occurrence, which may be a local binding rather than the external type — silently resolving to the wrong definition or returning `NotFound`.
- `send_request_and_wait()` discards plain notifications (no `"id"` field) silently and replies `null` to server-initiated requests (has both `"id"` and `"method"`). If ra sends an error as a plain notification it will be dropped; the 10,000-message loop will eventually surface a generic "Timed out" error.
- `drain_ra_messages()` is called on every main-loop iteration when ra is not stopped. It calls `try_read_message()` in a loop until the channel is empty. Missing a notification here only delays an `Indexing → Ready` transition; it does not lose a client response. `try_read_message()` will panic if called before `spawn_reader_thread()` — do not call it during the initialization phase before the reader thread is spawned.

## Technical Debt
- No versioning in the FIFO protocol. Old daemon + new client (or vice versa) will see JSON deserialization errors — the daemon logs and continues, the client gets an `anyhow::Error` from `read_message`. No diagnostic indicates a version mismatch.
- `ra_status` transitions to `Ready` via `$/progress` end notifications. If ra stops sending progress without completing (e.g., it crashes mid-index), the status stays `Indexing` until `wait_for_ready()` times out. No mechanism exists to detect a broken-but-live ra process after `Ready` is set — status stays `Ready` indefinitely while ra is unresponsive post-indexing.
- The FIFO open in `ipc::send_command()` (writing side, Unix) blocks without a timeout if the daemon disappears after `ensure_daemon()` returns. A killed daemon leaves an orphaned FIFO; the next client will block on open until a new daemon (or process) opens the read end.
- The 1 MiB message size limit is checked only on read, not on write. A client sending a pathologically large request will be rejected by the daemon but the client's `write_message()` will succeed silently.
- The background reader thread started by `spawn_reader_thread()` holds ra's `ChildStdout`. On daemon exit, calling `ra_child.wait()` will block until ra terminates; the reader thread exits naturally when ra closes stdout. No explicit join is needed — the thread is detached.
