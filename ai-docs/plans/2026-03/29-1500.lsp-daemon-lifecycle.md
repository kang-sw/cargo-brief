# Fix LSP daemon lifecycle: setsid + blocking touch

## Context

**Ticket:** `260329-bug-lsp-daemon-lifecycle` (Phase 1 + Phase 2)

**Problem:** Two issues: (1) daemon dies when parent shell exits because
`process_group(0)` only calls `setpgid(0,0)` — same session, new process
group — so SIGHUP from session teardown still reaches the daemon on macOS;
(2) `touch` returns before indexing completes, hiding ra crashes during
indexing from the user.

**Decisions from discussion:**
- Phase 1: Replace `process_group(0)` with `setsid()` via `pre_exec`.
- Phase 2: `touch` blocks by default until indexing finishes. `--no-wait`
  flag for fire-and-forget. `DaemonRequest::WaitForReady` with unlimited
  daemon-side timeout. Client prints progress dots every 3 seconds
  (`"Indexing . . . . . ."` pattern). Error includes `lsp.log` tail.
  Thread-based dot printing (not custom poll loop).

**Rejected:** Spinner (LLM-hostile). Custom poll loop for dots (IPC
duplication). Finite timeout for touch indexing wait.

- `src/lsp/process/unix.rs` — `configure_daemon_spawn()`: the one-liner to fix

## Conventions (verified from code)

- Daemon requests are `#[derive(Serialize, Deserialize, Debug)]` enum variants
  in `protocol.rs`. All query results use `DaemonResponse::QueryResult { output }`
  but `WaitForReady` is not a query — it should return `DaemonResponse::Ok`
  on success or `DaemonResponse::Error` on failure.
- `handle_request()` is a pure function: `&DaemonRequest` → `DaemonResponse`.
  But `WaitForReady` needs `wait_for_ready()` which mutates `ra_status`,
  `active_progress`, `had_progress` — these live in the main loop scope.
  The main loop already handles this pattern for query commands (lines 443-466):
  it calls `wait_for_ready()` before `handle_request()`. `WaitForReady` should
  follow the same pattern but with unlimited timeout.
- `send_command()` timeout is `Duration` → clamped to `c_int::MAX` ms via
  `try_into().unwrap_or(c_int::MAX)` (ipc/unix.rs:213). Passing
  `Duration::from_secs(i32::MAX as u64)` or `Duration::MAX` both clamp
  safely. Using `Duration::MAX` is cleanest.
- `cmd_touch` currently prints to stderr via `eprintln!`. Progress dots
  should also go to stderr (consistent with all `[lsp]` prefix messages).
- `LspCommand` variants with data use named fields (e.g. `References { symbol, quiet }`).
  `Touch` is currently a unit variant. Adding `--no-wait` makes it
  `Touch { no_wait: bool }`.
- `read_log_tail(path, max_lines)` in `client.rs` is `fn` (private).
  It needs to become `pub(super)` for `mod.rs` to call it.

## Implementation Steps

1. **Phase 1: `setsid()` in unix.rs**
   - File: `src/lsp/process/unix.rs`
   - Replace `cmd.process_group(0)` with:
     ```rust
     unsafe {
         cmd.pre_exec(|| {
             if libc::setsid() == -1 {
                 return Err(std::io::Error::last_os_error());
             }
             Ok(())
         });
     }
     ```
   - Update the doc comment to say "Detach daemon into a new session" instead
     of "Detach from parent's process group".
   - Delegation: main

2. **Add `WaitForReady` to protocol**
   - File: `src/lsp/protocol.rs`
   - Add `WaitForReady,` variant to `DaemonRequest` enum (after `Status`).
   - No new `DaemonResponse` variant needed — uses `Ok`/`Error`.
   - Delegation: main

3. **Handle `WaitForReady` in daemon main loop**
   - File: `src/lsp/daemon.rs`
   - The main loop's `is_query` gate (lines 443-466) uses a single
     `ready_timeout`. `WaitForReady` needs `Duration::MAX`. Restructure:
     ```rust
     // Determine wait timeout: WaitForReady gets unlimited, queries get ready_timeout
     let wait_timeout = match &request {
         DaemonRequest::WaitForReady => Some(Duration::MAX),
         DaemonRequest::References { .. }
         | DaemonRequest::BlastRadius { .. }
         | DaemonRequest::CallHierarchy { .. } => Some(ready_timeout),
         _ => None,
     };
     if let Some(timeout) = wait_timeout {
         if ra_status != RaStatus::Ready {
             if let Err(e) = wait_for_ready(
                 &mut transport, &mut ra_status, &mut active_progress,
                 &mut had_progress, start_time, timeout,
             ) {
                 // send error response, continue
             }
         }
     }
     ```
     This replaces the `is_query` boolean + single timeout with a per-variant
     `Option<Duration>`.
   - In `handle_request()`, add arm:
     ```rust
     DaemonRequest::WaitForReady => DaemonResponse::Ok {
         message: format!("ready (ra: {ra_status})"),
     },
     ```
     This arm runs AFTER `wait_for_ready()` succeeds in the main loop gate.
     If `wait_for_ready()` fails, the main loop already sends the error
     response (lines 458-465).
   - Delegation: main

4. **Add `Stopped` early-exit to `wait_for_ready`**
   - File: `src/lsp/daemon.rs`
   - Inside `wait_for_ready`, after the `read_message_timeout` call, add:
     ```rust
     if *ra_status == RaStatus::Stopped {
         bail!("rust-analyzer stopped unexpectedly during indexing");
     }
     ```
   - Primary crash detection is via transport channel disconnection
     (`read_message_timeout` returns `Err("rust-analyzer stdout closed")`,
     propagated by `?`). The `Stopped` check is a safety net for edge cases
     where the process exits but stdout pipe lingers.
   - Delegation: main

5. **Add `--no-wait` flag to CLI**
   - File: `src/cli.rs`
   - Change `Touch` from unit variant to:
     ```rust
     Touch {
         /// Return immediately after ensuring daemon is running (skip indexing wait)
         #[arg(long)]
         no_wait: bool,
     },
     ```
   - Delegation: main

6. **Update `run_lsp_command` dispatch**
   - File: `src/lsp/mod.rs`
   - Change match arm from `LspCommand::Touch => cmd_touch(td, wr, verbose)` to
     `LspCommand::Touch { no_wait } => cmd_touch(td, wr, verbose, *no_wait)`.
   - Delegation: main

7. **Make `read_log_tail` accessible from mod.rs**
   - File: `src/lsp/client.rs`
   - Change `fn read_log_tail(...)` to `pub(super) fn read_log_tail(...)`.
   - Delegation: main

8. **Rewrite `cmd_touch()` with blocking wait and progress dots**
   - File: `src/lsp/mod.rs`
   - Signature: `fn cmd_touch(target_dir, workspace_root, verbose, no_wait) -> Result<()>`
   - Logic:
     ```
     if no_wait:
       ensure_daemon(...)
       send Status with 5s timeout (current behavior)
       print status, return

     else:
       dir = ensure_daemon(...)
       // Start progress dots thread immediately
       stop_flag = Arc<AtomicBool>::new(false)
       dot_thread = spawn thread:
         eprint!("[lsp] Indexing ")
         loop:
           sleep 3s (check stop_flag every 100ms)
           if stop_flag: break
           eprint!(". ")
         eprintln!()  // newline on stop

       // Send WaitForReady with Duration::MAX
       // Daemon returns immediately if already Ready (wait_for_ready line 296)
       result = send_command(dir, WaitForReady, Duration::MAX)
       stop_flag.store(true, Relaxed)
       dot_thread.join()

       match result:
         Ok(DaemonResponse::Ok { message }):
           eprintln!("[lsp] {message}")
         Ok(DaemonResponse::Error { message }):
           log_path = dir.join("lsp.log")
           tail = read_log_tail(&log_path, 20)
           bail!("LSP daemon error: {message}\nDaemon log:\n{tail}")
         Err(e):
           log_path = dir.join("lsp.log")
           tail = read_log_tail(&log_path, 20)
           bail!("LSP daemon communication failed: {e}\nDaemon log:\n{tail}")
         _ -> bail!("Unexpected response")
     ```
   - No preliminary Status check needed — `WaitForReady` returns immediately
     when ra is already Ready (daemon-side `wait_for_ready` returns at line 296).
   - The dot thread checks `stop_flag` every 100ms to avoid sleeping 3s
     after completion. Pattern: loop 30 iterations of 100ms sleep, check
     flag each iteration, print dot after all 30.
   - **Known limitation:** `send_command` holds `flock` for the entire
     `WaitForReady` duration. While `touch` blocks, other `cargo brief lsp`
     commands are also blocked waiting for the flock. Same tradeoff as query
     commands but with a longer window. Mitigation: Ctrl-C the blocking
     `touch` releases the flock. This is acceptable — `touch` is inherently
     a "wait until ready" operation.
   - Delegation: main

## Testing Strategy

| Module | Approach | Rationale |
|--------|----------|-----------|
| `process/unix.rs` | Manual | `setsid()` effect requires spawning a real daemon; unit-testable only with process isolation which is heavyweight. Verify by: spawn daemon, close terminal, check daemon survives. |
| `protocol.rs` | Post-impl | Add roundtrip test for `WaitForReady` variant, following existing `roundtrip_*` test pattern. |
| `daemon.rs` | Manual | `handle_request` match is exhaustive — compiler enforces new arm. `wait_for_ready` with unlimited timeout is a parameter change, not logic change. |
| `cli.rs` | Post-impl | Verify `--no-wait` parses correctly via `cargo brief lsp touch --no-wait --help`. |
| `mod.rs` (cmd_touch) | Manual | Progress dots and blocking behavior require a live ra instance. Test manually: `cargo brief lsp touch` on a real project, verify dots appear and it blocks until ready. |

**Key scenarios for manual testing:**
1. `cargo brief lsp touch` — blocks, shows dots, completes when ra is ready
2. `cargo brief lsp touch --no-wait` — returns immediately (old behavior)
3. `cargo brief lsp touch` when already ready — returns immediately, no dots
4. Kill terminal during `cargo brief lsp touch --no-wait && sleep 60` — daemon survives (setsid fix)
5. `cargo brief lsp touch` when ra crashes during indexing — error with log tail

## Success Criteria

- Daemon survives parent shell exit (Phase 1)
- `cargo brief lsp touch` blocks until indexing completes or error
- `--no-wait` preserves fire-and-forget behavior
- Progress dots print every 3 seconds during wait
- Error messages include `lsp.log` tail for diagnosis
- `DaemonRequest::WaitForReady` roundtrips correctly in protocol tests
- Existing `cargo brief lsp status/stop/references/blast-radius/call-hierarchy`
  behavior unchanged
