# Nightly Toolchain Auto-Detection and Install Prompt

## Context

**Ticket**: `260330-feat-nightly-toolchain-auto-install` Phase 1.

**Problem**: cargo-brief requires nightly for `--output-format json -Z unstable-options`.
When nightly is missing, the error surfaces only after cargo fails — no proactive check
or install offer.

**Decisions from ticket**:
- Pre-check via `rustup which rustdoc --toolchain {toolchain}` (~10ms, acceptable).
- Interactive prompt when stderr is a TTY; actionable error otherwise.
- Read user input from `/dev/tty` (Unix) / `CONIN$` (Windows), not stdin.
- Shared helper `ensure_toolchain_available()` in `rustdoc_json.rs`.
- `AtomicBool` guard so the check runs at most once per process.
- Subcommands that don't invoke rustdoc (`ts`, `examples`, `code --no-deps`,
  `code --all-deps`, `lsp`, `clean`) are unaffected — they never call
  `generate_rustdoc_json` or `batch_generate_rustdoc_json`.

**Rejected**: avoiding nightly entirely, `RUSTC_BOOTSTRAP=1`, direct filesystem check.

## Relevant Files

- `src/rustdoc_json.rs` — Primary change target. Add `ensure_toolchain_available()`.
  Insert call at top of `generate_rustdoc_json()` (line 60) and
  `batch_generate_rustdoc_json()` (line 311). Existing toolchain-not-installed
  error handling (lines 118-122) becomes a fallback for edge cases.
- `src/cli.rs` — `GlobalArgs.toolchain` (line 533) default is `"nightly"`. No changes
  needed but informs what value flows into the check.
- `src/lib.rs` — All pipeline entry points that call `generate_rustdoc_json` or
  `pre_warm_cross_crate_json`. No changes needed — the check is inside
  `rustdoc_json.rs` functions.
- `src/cross_crate.rs` — Calls `generate_rustdoc_json` (lines 165, 779, 794, 937).
  No changes needed — covered by the internal check.

## Conventions (verified from code)

- Error messages go to stderr. Progress output uses `eprintln!` with `[cargo-brief]`
  prefix when verbose.
- `anyhow::bail!` for unrecoverable errors. `anyhow::Context` for wrapping.
- `std::process::Command` for subprocess invocation (used extensively in this file).
- No existing use of `std::io::IsTerminal` in the codebase — this will be the first.
- Platform-specific code pattern: `#[cfg(unix)]` / `#[cfg(windows)]` blocks in the
  same file (see `src/lsp/ipc/` for precedent), or inline `cfg` for small differences.

## Implementation Steps

1. **Add `ensure_toolchain_available()` function to `rustdoc_json.rs`**
   - Delegation: main
   - Signature: `fn ensure_toolchain_available(toolchain: &str) -> Result<()>`
   - Static `AtomicBool` (`TOOLCHAIN_CHECKED`) to skip repeat checks.
   - Run `rustup which rustdoc --toolchain {toolchain}` capturing output.
   - If exit code == 0: set flag, return Ok.
   - If exit code != 0 (toolchain missing):
     - If stderr is a TTY (`std::io::stderr().is_terminal()`):
       - Print prompt to stderr.
       - Read one line from `/dev/tty` (Unix) or `CONIN$` (Windows).
       - If `y` or `Y`: run `rustup toolchain install {toolchain}` with
         inherited stderr, check exit code. On success: set flag, return Ok.
         On failure: bail with install error.
       - If anything else: bail with "install it manually" message.
     - If not a TTY: bail with actionable error message (same as current
       behavior at line 118-122, but triggered proactively).
   - If `rustup` binary is not found (`.output()` returns
     `Err(NotFound)`): bail with "rustup not found" message suggesting
     manual installation.

2. **Insert check at top of `generate_rustdoc_json()`**
   - Delegation: main
   - Add `ensure_toolchain_available(toolchain)?;` as the first statement
     after the `use_cache` early-return check (line 79). The cache check
     should remain first — if cached JSON exists, no toolchain needed.

3. **No change to `batch_generate_rustdoc_json()`**
   - `batch_generate_rustdoc_json` is a pre-warming optimization. If nightly
     is missing, it fails silently (existing behavior for all errors) and the
     fallback per-crate calls in `cross_crate.rs` → `generate_rustdoc_json()`
     will trigger the prompt exactly once via the `AtomicBool` guard. Adding
     a separate check here would cause confusing double-messaging (warning
     from batch, then prompt from per-crate fallback).

4. **Add imports**
   - Delegation: main
   - `use std::io::IsTerminal;` and `use std::sync::atomic::{AtomicBool, Ordering};`
     at top of `rustdoc_json.rs`.

## Testing Strategy

| Module | Approach | Rationale |
|--------|----------|-----------|
| `ensure_toolchain_available()` | Manual | Requires interactive TTY and toolchain state manipulation. Cannot be unit-tested without mocking `Command`. |
| Integration (existing tests) | Post-impl verification | Run `cargo test` — existing tests use `--toolchain nightly` and already have nightly installed; they verify the check doesn't break the happy path. |

**Manual verification**:
- Rename/hide nightly toolchain temporarily, run `cargo brief api serde`,
  confirm prompt appears in terminal and error appears in piped mode.
- Verify `cargo brief ts ...` and `cargo brief examples ...` work without
  nightly (they never call the check).

## Success Criteria

- `cargo brief api self` on a machine without nightly: prompts interactively,
  installs on confirmation, succeeds.
- Same command piped (`echo "" | cargo brief api self`): prints actionable
  error without hanging.
- `cargo brief ts self '(function_item)'` works without nightly installed.
- Existing test suite passes unchanged (`cargo test`).
- The check adds < 50ms overhead to the first rustdoc invocation.
