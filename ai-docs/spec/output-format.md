# Output Format

cargo-brief produces text designed to be consumed by LLMs and developers who need a quick structural overview of a crate. The output is pseudo-Rust: valid enough for syntax highlighters but not compilable. Function bodies are replaced with `;`, hidden fields with a comment, and collapsed sections with `{ .. }`.

## Crate Header and Crate-Level Docs {#260423-crate-header}

Every output block opens with:

```
// crate <name>
```

For remote crates with a resolved version and active features:

```
// crate serde[1.0.217] features = ["derive"]
```

Crate-level `//!` documentation follows immediately as `//!` lines. A blank `//!` doc line renders as a bare `//!`. Suppression flags: `--no-docs`, `--compact`, `--no-crate-docs`, `--doc-lines 0`.

## Pseudo-Rust Philosophy {#260423-pseudo-rust-philosophy}

The output contract:

- **Syntax-highlighter valid** — a tool that parses Rust syntax should not error on the output.
- **Not compilable** — bodies, private fields, and deep modules are elided.
- **Visibility qualifiers reproduced** — `pub`, `pub(crate)`, `pub(super)`, `pub(in path)` appear on items exactly as declared.
- **Generics, where clauses, lifetimes reproduced faithfully** — predicate lists appear on functions, structs, enums, traits, type aliases, unions, and impl blocks.
- **`impl Trait` re-sugared** — synthetic generic parameters generated by the compiler for `impl Trait` positions are collapsed back to `impl Trait` form.
- **`$crate::` prefixes stripped** — macro-hygiene path prefixes are removed from rendered type paths.

## Module Structure and Depth Control {#260423-module-structure}

Root-level items render at column 0 with no wrapper. Submodules within the depth limit render as:

```rust
mod submodule {
    // ... items ...
}
```

Each nesting level adds 4 spaces of indentation. Modules beyond the depth limit collapse to:

```rust
mod deep { /* ... */ }
```

`--depth N` (default 1) sets the expansion depth. `--recursive` expands all submodules without limit.

### Glob-Private Module Inlining {#260423-glob-private-module-inlining}

When a private module is fully re-exported via `pub use private_mod::*`, the module block is suppressed. Its items appear inline at the parent level as if defined there. Neither the `mod private_mod { }` block nor the `pub use private_mod::*;` line appears in output.

## Item-Type Rendering

### Structs {#260423-struct-rendering}

Three variants:

**Unit struct:**
```rust
pub struct Name<G> where G: Bound;
```

**Tuple struct:**
```rust
pub struct Name<G>(pub T1, T2, /* private */) where G: Bound;
```

**Named-field struct (normal mode):**
```rust
pub struct Name<G> where G: Bound {
    pub field: T,
    // .. private fields
}
```

When all fields are private: `pub struct Name { .. }`.  
When no fields are private: no `// .. private fields` line.  
`--compact` collapses all plain structs to `pub struct Name<G> { .. }`.

### Enums {#260423-enum-rendering}

Normal mode lists all variants:

```rust
pub enum Event<T> where T: Send {
    Ready,
    Data(T),
    Error { code: u32, message: String },
}
```

`--compact` produces a single line if the result fits within 120 columns:

```rust
pub enum Event<T> { Ready, Data(..), Error { .. } }
```

If it exceeds 120 columns, falls back to one variant per line in compact form.

### Traits {#260423-trait-rendering}

```rust
pub trait Display: Debug {
    fn fmt(&self, f: &mut Formatter<'_>) -> Result;
    type Output;
    const MAX: usize;
}
```

`--compact` collapses to `pub trait Display: Debug { .. }`.

### Functions {#260423-function-rendering}

```rust
pub const async unsafe fn name<G>(param: T) -> Ret
where
    G: Clone + Debug;
```

Qualifier order: `const`, `async`, `unsafe`. Body always replaced with `;`. Where clauses use a multi-line block for two or more predicates, inline for one. HRTB (`for<'a>`), lifetime, type, and equality predicates are all reproduced.

`impl Trait` parameters are re-sugared from synthetic generic form:
```rust
// Before re-sugaring (what rustdoc JSON emits):
fn f<impl_T: T>(x: impl_T) -> impl_T

// After re-sugaring (what cargo-brief renders):
fn f(x: impl T) -> impl T
```

### Other Item Types {#260423-other-item-rendering}

**Type alias:**
```rust
pub type MyResult<T> where T: Clone = Result<T, MyError>;
```

**Constant:**
```rust
pub const MAX_SIZE: usize = 1024;
```

**Static:**
```rust
pub static mut COUNTER: AtomicU64 = AtomicU64::new(0);
```

**Union:**
```rust
pub union Bits {
    pub as_u32: u32,
    // ... private fields
}
```

**Macro:**
```rust
macro_rules! my_macro { /* ... */ }
```

## Inherent Impl Blocks {#260423-inherent-impl-rendering}

Inherent impl blocks render after their type definition:

```rust
impl<G> Name<G> where G: Clone {
    pub fn new() -> Self;
    pub fn len(&self) -> usize;
}
```

Only visibility-passing methods are shown. Empty impl blocks (no visible methods) are suppressed entirely. `--compact` collapses to `impl<G> Name<G> { .. }`.

## Trait Impl Collapsing {#260423-trait-impl-collapsing}

**Simple trait impls** (no associated types or constants) are collapsed into a per-type summary comment:

```rust
// Name: Clone, Debug, Display, Send, Sync
```

Traits are sorted alphabetically within the comment. Impls are grouped: forward impls (`impl Trait for Name`) produce the comment above; reverse impls (`impl Trait for OtherType`) produce `// OtherType: Trait` grouped by target type.

**Rich trait impls** (with associated types or constants) render expanded, with methods replaced by `// ..`:

```rust
impl Iterator for Name {
    type Item = u32;
    // ..
}
```

**Negative impls** (`impl !Send for Name`) always render expanded.

**Blanket and synthetic impls** are hidden by default. `--all` makes them visible and disables collapsing for all impls.

## Re-Export Rendering

### Named Re-Exports {#260423-named-reexport-rendering}

`pub use` items that resolve in the local crate index render with a kind annotation:

```rust
pub use crate::inner::Widget; // struct
pub use crate::inner::OldName as NewName; // trait
```

Supported kind labels: `struct`, `enum`, `trait`, `fn`, `type`, `const`, `static`, `macro`, `use`.

In default mode (`--no-expand-glob` absent), named re-exports from the local crate are replaced by the full inlined definition of the target item rather than a `pub use` line.

### Glob Re-Exports {#260423-glob-reexport-rendering}

Glob re-exports (`pub use source::*`) are expanded inline by default:

- **Private module source** — module block suppressed; items appear at parent level (see [Glob-Private Module Inlining](#260423-glob-private-module-inlining)).
- **External crate source** — full definitions of all reachable items inlined at the re-export site.

`--no-expand-glob` suppresses expansion. The `pub use source::*;` line is emitted verbatim and no inlining occurs.

Cross-crate named re-exports (`pub use serde_core::Serialize;`) are also expanded inline by default, replacing the `pub use` line with the target item's full definition. This uses the same `--no-expand-glob` toggle.

## Doc Comment Handling {#260423-doc-comment-handling}

Doc comments from rustdoc JSON are reproduced verbatim as `///` lines, indented to match their item. Empty doc lines produce a bare `///`.

### Density Flags {#260423-density-flags}

| Flag | Effect |
|---|---|
| `--no-docs` | Suppress all `///` doc comment lines |
| `--no-crate-docs` | Suppress the crate-level `//!` block only |
| `--doc-lines <N>` | Limit each item's doc output to the first N lines; `0` equals `--no-docs` |
| `--compact` | Implies `--no-docs`; additionally collapses item bodies (see per-item sections above) |

Flags interact: `--doc-lines 3` limits to 3 lines; `--compact` overrides to 0; `--no-crate-docs` applies independently of the other flags.

## Attribute Rendering {#260423-attribute-rendering}

### Default Attributes (always shown)

```rust
#[deprecated]
#[deprecated = "use new_fn instead"]
#[deprecated(since = "1.5.0", note = "use new_fn instead")]
#[non_exhaustive]
```

These render regardless of `--verbose-metadata`.

### Verbose Attributes (`--verbose-metadata`)

```rust
#[must_use]
#[must_use = "returns an error if dropped"]
#[repr(C)]
#[repr(transparent)]
#[repr(align(8), C)]
#[no_mangle]
#[macro_export]
#[export_name = "my_symbol"]
#[target_feature(enable = "avx2")]
```

`AutomaticallyDerived` and `Other` attribute variants are always suppressed.

## Feature-Gate Annotations {#260423-feature-gate-annotations}

Items that are conditionally compiled behind a `cfg(feature = "...")` predicate emit a `#[cfg(...)]` line in the output. The annotation appears immediately after the item's doc comment and before any other attributes:

```rust
/// Enables async runtime support.
#[cfg(feature = "async")]
pub fn spawn<F: Future>(f: F) -> JoinHandle<F::Output>;
```

Complex predicates round-trip faithfully:

```rust
#[cfg(all(feature = "serde", feature = "std"))]
pub struct SerdeValue { .. }

#[cfg(any(feature = "net", feature = "io"))]
pub mod runtime;
```

If the raw cfg attribute cannot be parsed, a fallback comment is emitted instead of a `#[cfg(...)]` line:

```rust
// cfg: #[attr = CfgTrace([...])]
```

`--no-feature-gates` (a FilterArgs flag) suppresses all feature-gate annotation lines from the output. No other attributes are affected.

> [!note] Constraints
> - Feature-gate annotations are informational only — they do not affect which items are visible. An item that fails the observer-position visibility check is still suppressed regardless of any cfg predicate.
> - Only `cfg(feature = "...")` predicates and their compositions (`all`, `any`, `not`) are annotated. Platform predicates (`cfg(unix)`, `cfg(target_arch = "x86_64")`) are included when they appear in the same cfg expression.

## Item-Kind Filtering {#260423-item-kind-filtering}

The default set includes all common item kinds. Each `--no-*` flag removes one kind:

| Flag | Excluded |
|---|---|
| `--no-structs` | Structs |
| `--no-enums` | Enums |
| `--no-traits` | Traits |
| `--no-functions` | Functions |
| `--no-aliases` | Type aliases |
| `--no-constants` | Constants **and** statics |
| `--no-unions` | Unions |
| `--no-macros` | Macros |

`--all` adds blanket impls, auto-trait impls, and synthetic impls to the output, and disables trait impl collapsing.

## Search Output Format {#260423-search-output-format}

Search results produce one line per item, no `pub` prefix. The full module path is used as the item name.

Header:
```
// crate <name> — search: "<pattern>" (N results)
```

Per-item line formats by kind:

| Kind | Format |
|---|---|
| Function | `[const] [async] [unsafe] fn path::name<G>(params) -> Ret where P1, P2;` |
| Struct (unit) | `struct path::Name<G> where ...;` |
| Struct (tuple) | `struct path::Name<G>(T1, T2) where ...;` |
| Struct (plain) | `struct path::Name<G> where ... { .. };` |
| Enum | `enum path::Name;` |
| Trait | `trait path::Name;` |
| Union | `union path::Name;` |
| Field | `field path::Struct::field_name: T;` |
| Variant (unit) | `variant path::Enum::Name;` |
| Variant (tuple) | `variant path::Enum::Name(T1, T2);` |
| Variant (struct) | `variant path::Enum::Name { field: T };` |
| Constant | `const path::NAME: T = value;` |
| Static | `static [mut] path::NAME: T;` |
| Type alias | `type path::Name<G> = T;` |
| Macro | `macro path::name!;` |
| Associated type | `type path::Type::Assoc = T;` |
| Associated const | `const path::Type::CONST: T = value;` |
| Re-export | `use source::path;` or `use source::path as Alias; // kind` |

**Search-mode doc comments:** the first non-empty doc line renders as `/// <line>` immediately above the item line. Suppressed by `--no-docs` or `--compact`.

**Search-mode attribute markers:** `[deprecated]` and `[non_exhaustive]` appear as inline prefix tags on the same line as the item (not as `#[...]` syntax).

**Inline impl summary** (appended to struct, enum, and union lines):
```
struct path::Name; // impl (3 methods), impl Clone, impl Debug + 2 more
```
Capped at 5 entries before `+ N more`. Synthetic and blanket impls excluded unless `--all`.

Cross-crate search includes struct fields, enum variants, and union fields with the same formatting as local-crate results.

### Member Display {#260423-search-member-display}

By default, member items (fields, methods, variants) are hidden in search results unless a search token exactly matches the member's own name.

`--members` disables suppression and shows all members of matched types.

Consecutive items sharing a parent path use **collapsed continuation lines** to avoid repeating the full path:

```
struct path::to::Widget;
        -::width: f32;
        -::height: f32;
        -::render(&self) -> Output;
```

The `-::` prefix is padded to align under the first `::` segment of the parent path.

`--methods-of <TYPE>` is an exact parent-type match (not substring). It bypasses member suppression and shows only the named type's fields, methods, and variants.

### Sorting and Pagination {#260423-search-sort-pagination}

Default sort order: functions first, then structs, enums, traits, unions, fields, variants, constants, statics, type aliases, macros, associated types, associated constants, re-exports. Secondary sort: alphabetical by full path. With `--members`, sort is path-based only.

`--limit N` shows the first N results. `--limit OFFSET:N` skips OFFSET results then shows N.

Pagination comments:
```
// (skipped 20 results)
...results...
// ... and 15 more results
```

Zero-result hint (when pattern has 4+ words):
```
// hint: search uses AND matching — all 5 words must appear in one item's path. Try fewer words.
```

## Summary Output Format {#260423-summary-output-format}

`cargo brief summary` produces a compact module-level table of contents.

Header:
```
// crate <name>
```

Module lines (column-aligned):

```
mod io;          // 4 traits, 15 structs, 8 fns
mod io::buf;     // 2 traits, 3 structs, 5 fns
// root:         // 1 trait, 2 structs
```

Rules:
- One line per submodule with at least one visible item.
- `// root:` covers items defined directly at the queried module level.
- Item kind columns appear in fixed order: traits, structs, enums, fns, types, consts, macros, unions.
- Zero-count kinds are omitted.
- All `//` comments align to the same column (padded).
- Empty modules (zero visible items) are omitted entirely.
- For cross-crate facade crates, sub-crate module lines are prefixed with the accessible path: `mod render::render_resource; // ...`.
